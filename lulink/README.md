# 鹿传

纯前端、离线、无服务器的动态二维码文件传输工具。

## 使用方法

1. 两台设备都打开本网页。
2. 发送端：进入“发文件” → 选择单个文件 → 生成动态二维码。
3. 接收端：进入“收文件” → 启动摄像头 → 对准发送端二维码。
4. 所有分片收齐后会执行 CRC32 与 SHA-256 校验，通过后提供文件下载。

## 推荐启动方式

摄像头 API 通常要求安全上下文。推荐在电脑上运行：

- macOS：双击 `start-local-server.command`
- Windows：双击 `start-local-server.bat`

然后访问 `http://localhost:8080`。

## 浏览器要求

接收端优先使用浏览器原生 `BarcodeDetector` 识别 QR Code；当该接口不可用时，会自动切换到内置的 `jsQR` 兼容识别器，因此也支持缺少 `BarcodeDetector` 的 Safari/iOS 浏览器。摄像头仍要求 HTTPS 或 localhost 安全上下文。

项目内置的 `jsQR` 使用 Apache License 2.0，许可证见 `jsQR-LICENSE.txt`。

## 协议与校验

- QR 固定使用 Version 22-L，发送端完全离线生成，单个 QR 文本载荷上限为 1003 字节。
- 文件可按 576/640/704 字节分片，默认单帧数据量为 704 字节。
- 默认 250 ms 帧间隔下，编码侧理论速率约 22.5 kb/s；扣除周期性元数据帧后，有效目标约 21.3 kb/s。实际速率受摄像头帧率、屏幕清晰度、距离和环境光影响。
- 每个数据帧带文件会话 ID、序号、总帧数和 CRC32。
- 元数据帧周期性重复，接收端可从传输中途加入。
- 元数据包含文件名、MIME、文件大小、总帧数、分片大小与完整文件 SHA-256。
- 接收完成后按序重组，并再次验证长度与 SHA-256。

## 说明

二维码传文件的吞吐量天然较低，适合小文件、配置数据、文本、证书、小图片等场景。大文件会产生大量帧，不适合与 Wi‑Fi / 蓝牙等高速链路竞争。

Roylyl Music是个人主页下的独立音乐子站，使用原生HTML、CSS和JavaScript，无需登录，也无需安装前端依赖或执行构建。桌面端和手机端共用一套曲库，支持专辑浏览、同步歌词、播放队列与离线缓存，并提供深色、浅色和跟随系统三种外观。

## 开始使用

### 在线收听

打开[Roylyl Music](https://roylyl.github.io/music/)，从“全部歌曲”“专辑”“歌单”“设置”四个入口开始。网页采用RoyTools的主题色与圆角控件，默认跟随系统外观。选择歌曲即可播放。点击底部的专辑封面进入全屏播放页，在封面与歌词之间切换。每次打开播放器会自动检查曲库版本，也可在设置底部点击“检查曲库更新”；歌曲、专辑和新增歌单一起同步，断网时继续使用已保存的曲库与完整缓存的歌曲。

iPhone可在Safari中选择“分享→添加到主屏幕”，从桌面图标打开播放器。其他支持PWA的浏览器可使用浏览器提供的安装入口。首次使用需要联网；系统播放控制和后台运行受浏览器及系统策略影响，iPhone音量由系统控制。

### 本地预览

安装Python3后，在网站仓库根目录运行：

```sh
# macOS/Linux
python3 scripts/preview.py 8037
```

```powershell
# Windows
py -3 scripts/preview.py 8037
```

打开[本地播放器](http://127.0.0.1:8037/music/)。预览服务器默认仅监听本机，支持音频分段请求。请通过HTTP地址访问页面；直接双击HTML文件无法使用完整的PWA缓存功能。

本地预览默认仍读取远程音乐库，首次播放需要联网。只浏览和播放网页时，无需下载整个Music仓库。

## 播放与浏览

| 功能 | 使用方式 |
| --- | --- |
| 专辑与歌曲 | 浏览专辑、搜索歌曲、筛选歌手，按发行年份等条件排序。点击专辑封面进入曲目列表，点击播放键开始播放。 |
| 顺序与随机播放 | 从当前专辑或歌单开始播放；随机模式整轮不重复，播完一轮后重新打乱。上一首沿实际播放历史返回。 |
| 播放队列 | 打开时定位当前曲目，高亮待插队歌曲；手机端标题与关闭按钮保持在列表上方。 |
| 同步歌词 | 按时间滚动和高亮LRC歌词，同一时间的原文与译文一起显示；无时间标签的歌词以纯文本展示。 |
| 全屏播放 | 桌面双栏、手机纵向布局，展示封面、歌词及音源格式、码率、采样率、声道和文件大小。 |
| 歌曲更多菜单 | 下载当前歌曲、分享歌曲、查看专辑和查看歌手；多位歌手可展开选择。 |
| 迷你播放器 | 固定悬浮在页面底部，页面转场时保持原位；手机上左右滑动切歌。 |
| 进度调节 | 拖动时预览目标时间，松手后才跳转；首次从歌单打开歌曲即可操作。 |
| 定时关闭 | 全屏更多菜单可选30分钟、1小时、2小时、3小时或自定义分钟数；显示倒计时，到时暂停并保留进度。 |
| 播放记忆 | 保存曲目、进度、队列、插队和播放模式，刷新后恢复，等待用户点击播放。 |

### 下一首插队

歌曲右侧的“下一首播放”会加入插播队列，多首歌曲按照点击先后播放。原列表中的歌曲保留：

```text
原顺序：A→B
播放A时先添加G、再添加H：A→G→H→B
播放G时继续添加I：A→G→H→I→B
```

重复添加同一首待插播歌曲不会重复加入，也不会改变已经排好的顺序；当前歌曲也可以插播，从头再听一次。插播优先于随机和单曲循环，结束后继续原来的播放顺序。

在更多菜单中可“取消此次插队”或“清空待插队”。添加、取消和清空后，底部提示提供5秒撤销入口。开始播放新的专辑或列表会清除旧插队。

### 系统控制与播放恢复

播放器通过Media Session提供锁屏和系统媒体控制。收到暂停或音频中断时保存位置；中断结束后等待用户恢复，避免打断其他应用的音频。网页依赖系统发送耳机暂停事件，不能直接读取耳机佩戴状态。

后台切歌和系统续播优先发起音频播放，再更新界面。启动请求卡住时会尝试一次保留进度的重新加载；加载失败会提供“重试/跳过”。主动暂停、系统中断和新的播放操作会使旧恢复请求失效。

“设置→播放诊断”保留最近24小时最多120条播放事件，可复制诊断或导出JSON日志；剪贴板不可用时显示可手动复制的文本。记录仅保存在当前浏览器中，不自动上传。

## 离线与缓存

成功在线打开后，网页和曲库目录可离线重新打开；断网时可播放已经完整保存的歌曲。在“设置→音乐下载→已下载曲目”中可筛选和管理歌曲，单曲删除需要再次确认。

进度条的蓝色部分表示已播放，缓存条显示整曲下载进度。开启音乐缓存后，开始播放即持续保存整首音频；当前歌曲完整保存后再预加载下一首。

专辑封面按资源地址和版本共用缓存，同一专辑的歌曲、列表和播放器复用同一份图片。已缓存的封面直接从本地读取，浏览与批量下载共用进行中的请求；多个页面同时打开也不会各自下载同一张封面。资源版本变化或手动清理缓存后才重新获取，失败请求会短暂限速，仍可点击失败的封面立即重试。

在设置中可以调整：

- 音乐缓存上限：关闭、256MB、512MB、1GB、2GB、4GB、8GB或无限，默认无限。容量按十进制计算，无限仍受浏览器配额和设备剩余空间限制。
- 下一首预加载：默认开启，会提前下载下一首完整音频；流量有限时可关闭。
- 下载单曲、整张专辑、整个歌单或全部歌曲，也可批量下载歌词和专辑封面。
- 下载窗口显示进度与速度，支持取消和后台下载；浏览器允许通知时可显示系统下载进度通知。移动端进度通知每60秒更新一次，转入后台和任务结束时更新状态。
- 独立清理音乐、歌词和专辑封面缓存，或确认后删除全部下载与缓存。
- 全屏播放时保持亮屏，默认开启；需浏览器支持屏幕唤醒锁。

曲库和歌单更新会直接同步到当前页面，保留正在播放的歌曲和播放进度。刷新页面即可加载新版界面。浏览器关闭页面或系统回收后台任务后，下载可能中断；后台运行与系统通知能力取决于浏览器。Service Worker仅管理`/music/`，不影响主站；清理旧网页版本时保留音乐、歌词和封面缓存。

## 曲库与歌单维护

曲库、歌单、音频、歌词和专辑封面统一由[Roylyl/Music](https://github.com/Roylyl/Music)发布。网页与RoyTools使用同一套版本检查和本地缓存规则，新增歌曲、专辑或歌单时只需更新Music仓库。

| Music仓库中的文件 | 用途 |
| --- | --- |
| [catalog-version.json](https://github.com/Roylyl/Music/blob/main/catalog-version.json) | 轻量版本清单；打开播放器时先读取它。 |
| [catalog.json](https://github.com/Roylyl/Music/blob/main/catalog.json) | 同一版本的歌曲、专辑资料、歌单和音频参数。 |
| [tracks.json](https://github.com/Roylyl/Music/blob/main/tracks.json) | 可播放曲目索引，保留稳定的歌曲ID与媒体相对路径。 |
| [playlists.json](https://github.com/Roylyl/Music/blob/main/playlists.json) | 歌单、收藏状态和曲目映射，支持新增任意歌单。 |

当前统一曲库版本从1.0.0开始。客户端发现版本变化后读取并保存完整目录，校验成功才替换本机目录；版本文件与目录尚未同时发布、连接失败或断网时，保留已有曲库。已缓存的歌曲不会因目录更新被自动删除。

### 发布曲库更新

在Music仓库中添加音频、歌词和封面，维护曲目与歌单资料，再在Music仓库根目录运行`node scripts/publish-catalog.mjs`生成新版本目录，并按[Music仓库的维护说明](https://github.com/Roylyl/Music#更新曲库与歌单)发布。版本清单和目录应与对应媒体文件一起发布，不需要修改本网站或重新打包RoyTools。

专辑列表根据曲目自动生成；歌单列表根据云端歌单目录生成，新歌单会自动显示名称和歌曲数量。歌曲ID用于关联歌单、分享链接及播放记忆，应保持稳定。Apple Music中的修改需要先导入到Music仓库的歌单资料，再发布曲库版本；访客不能更改导出的喜欢状态。

封面直接读取Music仓库中的原始封面路径，使用资源版本区分缓存。分享歌曲时优先使用[独立分享页](share/)，卡片信息包含歌名、歌手、专辑和封面；封面直接引用Music仓库已有的JPEG/PNG原图，网站不重复保存封面文件。新增歌曲尚无独立分享页时，分享链接仍能打开当前曲库中的对应歌曲。

更新独立分享页时，运行`python music/scripts/generate-share-pages.py`，同时更新页面与分享索引。歌曲、专辑和歌单的自动同步仍以Music仓库为准。

### 网页界面更新

[页面内置目录](data/catalog.json)仅用于首次打开和无本地记录时的备用曲库。日常曲库更新不需要重写它，也不需要修改网页的资源版本。

电脑端和手机端共用播放器、下载、设置和曲库同步逻辑。电脑端保留侧栏与宽屏播放器，手机端采用与RoyTools一致的四入口首页；两端设置都包含曲目、歌词和封面下载、下载管理、播放诊断、日志导出及安装与更新。新歌单自动使用通用歌单图标，“我喜欢”“鹿”和“深圳”保留专用图标。

在“设置→安装与更新”可以查看安装方式和检查界面更新，新版就绪后点击刷新；应用安装与曲库更新分别处理。

修改网页代码时，再配套更新[index.html](index.html)、[shell.js](shell.js)、[app.js](app.js)和[audio-worker.js](audio-worker.js)中的网页资源版本。Service Worker只管理播放器页面，保留已保存的曲库与媒体缓存。
